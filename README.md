# SBL — приложение кофейни

Актуальная объединённая версия приложения SBL, кассы и Supabase backend.
Expo 54 · React 19 · React Native 0.81 · Supabase (Postgres, Auth, Realtime).

## Основные возможности

- Единственная точка: Томск, проспект Ленина, 72. Работа ежедневно 11:00–20:00
  по Asia/Tomsk, новые заказы до 19:55, приготовление обычно 3–5 минут.
- Самовывоз и оплата при получении. Онлайн-эквайринг не подключён.
- Меню и цены читаются из `products`; фотографии — из `image_override_url`.
  Клиент показывает только позиции с подключённой фотографией; пустые разделы
  скрываются. Полный каталог остаётся для проверки корзины, добавок и истории.
- Оформление через `create_pickup_order`: сервер проверяет контакт, время,
  наличие, quote v2, цены, бонусы и подарок. Повтор использует тот же ключ
  идемпотентности; после неизвестного сетевого исхода новый заказ автоматически
  не создаётся.
- Касса принимает заказы и меняет статусы. Выдача требует подтверждения оплаты.
  Продажа в СБИС вносится сотрудником вручную; автоматического экспорта нет.
- Бонусы и серия посещений подтверждаются сервером. Гостевая сессия сохраняется
  на устройстве; её удаление может привести к потере доступа к гостевой истории.
- **Вход обязателен для заказа (с 31 октября).** Гость видит только меню; добавить
  в корзину, оформить заказ, добавить в избранное или повторить заказ можно после
  входа по номеру телефона (экран `Login`). Виджеты на Home и пустая корзина ведут
  на вход. Проверка только клиентская: сервер всё ещё принимает заказы от
  анонимной сессии, жёсткий запрет нужен миграцией после подключения SMS.
- **Режим администратора.** При `EXPO_PUBLIC_ADMIN_LOGIN=true` и выключенном SMS
  (`PHONE_AUTH_ENABLED=false`) любой номер и любой код входят в локальный аккаунт
  (`adminSignIn` в `lib/accountService.js`, ключ `sbl_admin_account`). Для релиза
  флаг обязан быть `false`; в `.env.example` он выключен.
- **Добавки по типу позиции** (`lib/additionsPresentation.js`): без дублей, имена
  очищены от «+/-»; еда не получает молоко и сиропы, напитки — масло, икру, сыр и
  т. д.; чай, маршмеллоу и подобное не предлагаются к кофе. Альтернативное молоко
  (кокосовое, миндальное, безлактозное) — одно на напиток, 120 ₽, один SKU по
  объёму. Правила по видам напитков (`ALLOWED`) основаны на практике бариста,
  не на жёстком стандарте. Список вкусов сиропов владелец пришлёт позже. Строки
  с несовместимыми добавками при «повторить заказ» пропускаются.
- Экран «Подробнее»: блок КБЖУ плавно выезжает (opacity + сдвиг, 320/180 мс,
  учитывает reduce motion). Баннер активного заказа на Home выровнен отступами.
- Утверждённый дизайн: Onest; названия карточек 15px/400, цены 16px/600;
  палитра «Светлый минерал», серебряная карта, янтарный огонёк и общий перелив
  фирменных кнопок. Фото товаров и цветовые атмосферы сохранены.

## Запуск

Требуется Node.js и npm. Установка зависимостей по зафиксированному lock-файлу:

```sh
npm ci
npm start
```

Веб-режим: `npm run web`. Локальная проверенная экспортированная версия:

```sh
npm run build:check
node work/serve-integration.cjs
```

Адрес: http://127.0.0.1:8094/. `build:check` экспортирует JS и ресурсы для web,
Android и iOS; это не сборка APK/IPA и не публикация в магазинах.

Панель кассира и инструменты работы с фотографиями:

```sh
node work/serve-design-tools.cjs
```

- Касса: http://127.0.0.1:8096/cashier/
- Редактор фото: http://127.0.0.1:8096/photo-editor/

Для кассы нужен настоящий staff-аккаунт. Пароли в репозиторий не включаются.

## Настройки и ключи

Шаблон настроек — `.env.example`. Переменные URL и публичного ключа Supabase
задавайте вместе. Публичный ключ клиентского приложения не даёт административных
прав: доступ ограничен RLS и серверными RPC.

Секретные ключи Supabase, СБИС, SMS и push хранятся только на сервере или в
локальном окружении, вне Git. Диагностика СБИС принимает `SBIS_APP_CLIENT_ID`,
`SBIS_APP_SECRET`, `SBIS_SECRET_KEY` из окружения.

В Supabase должен быть разрешён анонимный вход. Для обновления статусов
Realtime включается для `orders`/`order_items`. Перед сменой проекта необходимо
проверить схему, права и применённые миграции.

## Что ещё требуется перед релизом

- **SMS:** экран использует настоящий OTP-контракт Supabase, но отправка
  отключена (`EXPO_PUBLIC_PHONE_AUTH_ENABLED=false`) до выбора и настройки
  провайдера. Произвольные коды принимает только режим администратора
  (`EXPO_PUBLIC_ADMIN_LOGIN=true`), в релизе он выключен. Для App Store ревьюеру
  понадобится рабочий вход или демо-аккаунт.
- **Push:** очередь, повторы, квитанции и настройки подготовлены; нужны
  native credentials, развёртывание worker и отдельное включение.
- **Новости и акции:** админка подготовлена в кассе; миграция
  `20261029120000_app_publications.sql` применена в рабочей базе 31 октября.
  Порядок включения — `work/publications/ACTIVATION.txt`.
- **iOS / App Store:** нужны Apple Developer Program (99 $/год, проверка
  документа через приложение Apple Developer), политика конфиденциальности,
  скриншоты, анкета App Privacy, ключи APNs. Сборка — `eas build -p ios`, отправка
  — `eas submit -p ios`. В `app.json` текст запроса геолокации сейчас в
  испорченной кодировке — исправить до отправки.
- **Сервер:** проверка совместимости добавок и подтверждённого телефона на стороне
  базы не сделана (только клиент). Делать после SMS и только по явной команде.
- **Контакты и документы:** по решению владельца остаются пометки
  «Нужно заполнить перед запуском». Юридические данные не выдуманы.
- **Телефоны и магазины:** требуется проверка реальной Android/iOS-сборки,
  разрешений, клавиатуры, жестов, уведомлений и публикационных материалов.

## Миграции и база

Актуальная схема и миграции находятся в `supabase/migrations/`.
Миграции `20261029100000_pickup_checkout.sql` и
`20261029110000_notifications.sql` владелец уже выполнил вручную 29 октября:
получены успешные результаты и 64/64 структурных проверок.
Повторно применять их к рабочей базе без проверки истории нельзя.
Ручной SQL от 18 октября (таксономия меню, хранилище фото, бэкап products)
сохранён в `supabase/applied-manually/` как история; это не миграции.

Обычный Git push, запуск приложения и клиентские проверки не развёртывают
Edge Functions и не изменяют схему базы. Подробности активации:
`work/PICKUP_RELEASE_ACTIVATION.txt`.

Для локальных SQL-проверок требуется Docker/Supabase CLI. Сценарии сброса
тестовой базы не предназначены для запуска на рабочем Supabase.

## Проверки

```sh
npm run check:integration
npm run build:check
node work/release-review.cjs --summary
```

Интеграционный набор содержит 27 сценариев: цены, наличие, идемпотентность,
конкурентные сессии, бонусы, награды, касса, уведомления, фотографии, маска
телефона, карта, анимации и фактическое применение Onest.

SQL-тесты и инструкции включения находятся в `work/`. Они не являются командой
применить изменения к рабочей базе. Проверка видимости меню использует снимок
каталога `work/fixtures/menu-photo-catalog.json` без данных клиентов и заказов.

## Обслуживание ресурсов

Редактор `work/photo-editor/` экспортирует настройки кадрирования; инструкция
находится в его папке. Выбранные шрифты и лицензия находятся в
`assets/fonts/onest/`, исходный variable-шрифт — в `source/`. Для повторной
генерации статических начертаний нужен Python с FontTools и скрипт
`work/typography-onest/build-fonts.py`; обычному запуску приложения это не нужно.

Для обновления атмосфер фотографий нужен Python с Pillow, снимок каталога и
папка с исходными фото, имена которых совпадают с последней частью URL:

```sh
python work/photo-tools/build-app-palettes.py work/fixtures/menu-photo-catalog.json /path/to/photos
node work/photo-tools/build-app-palettes.cjs
```

Второй скрипт обновляет `data/product-palettes.json`; с `--check` он только
сравнивает результат. Сэмплы и кэш фото не включаются в Git. Эти инструменты
не загружают фотографии в Supabase и не меняют исходные изображения.

## Основные файлы

- `App.js`, `screens/`, `components/`, `navigation/` — клиент и навигация.
- `lib/`, `hooks/`, `loyalty/` — каталог, корзина, заказ, сессия и лояльность.
- `theme/`, `assets/brand/`, `assets/fonts/onest/` — выбранный дизайн и локальные
  ресурсы. Лицензия Onest и происхождение файлов приложены.
- `data/menuData.js` — справочные составы и КБЖУ; каталог и окончательные цены
  приходят из Supabase.
- `data/photo-compositions.json` — настройки кадрирования по UUID и точному URL.
- `data/product-palettes.json` — атмосферы, привязанные к точным URL фотографий.
- `supabase/` — миграции, серверные функции и локальная конфигурация.
- `kassa-terminal/` — касса, ручной учёт СБИС и раздел публикаций.
- `work/` — проверки, инструкции, редактор и инструменты обслуживания ресурсов.

Локальные `.env`, зависимости, экспортированные сборки, кэши и скачанные копии
сторонних веб-страниц исключены из Git. Старые концепты, скриншоты и аудиты
сохранены локально у владельца, но в репозиторий не входят. Исходные материалы
меню вне этой папки приложения не нужны для обычного запуска клиента.
