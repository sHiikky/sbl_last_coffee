# SBL coffee

Приложение кофейни SBL coffee и веб-панель сотрудников. Исходники обновлены **27 ноября 2026 года**, с подключением к собственному REG.RU VPS.

Приложение: меню, самовывоз, профиль, бонусы и история заказов. Админка: заказы, статусы приготовления, каталог, стоп-лист, публикации и промокоды.

## Быстрый запуск приложения

Нужны **Node.js 22.13+ из ветки 22** либо **24.3+ из ветки 24** и npm. Установите зависимости по lock-файлу:

```sh
npm ci
```

Создайте локальный `.env` из `.env.example`. В PowerShell:

```powershell
Copy-Item .env.example .env
npm start
```

В macOS/Linux: `cp .env.example .env`, затем `npm start`.

Пример настроен на VPS и содержит только публичный клиентский ключ `anon`. Адрес и ключ меняются **вместе**. Пароли базы, SMSC и ключ `service_role` в клиент не добавляются. После изменения `.env` перезапустите Metro; уже собранный APK от этого не обновится.

**Важно:** облачный Supabase выведен из работы. Если адрес и ключ не заданы, клиент подключается к VPS (`https://31.31.207.216/coffee`, публичный ключ `anon`). Для другого сервера задайте обе переменные вместе через `.env` или окружение сборки. Отключённые в окружении функции входа автоматически не включаются.

### Браузер

```sh
npm run web
```

Адрес покажет Expo CLI. Приложение и касса запускаются отдельно.

### Expo Go на iPhone / Android

Для этой версии нужен **Expo Go с поддержкой SDK 58**. Expo Go для SDK 54 с ней несовместим. ПК и телефон можно подключить к одной сети; для доступа через интернет:

```sh
npx expo start --go --tunnel ngrok
```

Отсканируйте QR, который выдаст текущий сервер. Туннель временный и работает, пока запущен Metro. Expo Go может потребовать вход в Expo-аккаунт. Вход — по звонку на номер телефона. Push-уведомления в этом режиме не проверяются.

## Запуск админки

Из корня репозитория, при установленном Python 3:

```sh
python -m http.server 8098 --bind 127.0.0.1 --directory kassa-terminal
```

Откройте **http://127.0.0.1:8098/**. Не запускайте HTML через `file://`. Для входа нужна учётная запись сотрудника; права проверяет сервер. Подробности — [README админки](kassa-terminal/README.md).

Панель опубликована отдельно на **https://31.31.207.216/coffee/kassa/**. Публикация 27.11 проверила 19 файлов; вход сотрудника, загрузка фото и полный сценарий на кассовом ПК ещё требуют проверки. Публикация исходников на GitHub сама по себе не обновляет эту установку.

Для запроса удаления без установленного приложения опубликована **https://31.31.207.216/coffee/account-deletion/**: инструкции и письмо на `hello@sbleskom.ru`. Это запрос с последующей проверкой владельца аккаунта, а не мгновенное удаление по нажатию кнопки. Удаление из профиля приложения реализовано отдельно; фактическое удаление тестового аккаунта на VPS ещё предстоит проверить.

## Как работает заказ

- Точка: Томск, проспект Ленина, 72; часы 11:00–20:00 по `Asia/Tomsk`, новые заказы до 19:55.
- Сервер проверяет наличие, цены, добавки, промокоды, бонусы, подарки и повторные запросы. Итог из клиента не считается доверенным.
- Кассир принимает заказ, отмечает приготовление, готовность и выдачу. Для выдачи требуется подтверждение оплаты.
- Пятиминутный таймер в приложении — ориентир. Истечение таймера само не переводит заказ в готовые.
- Бонусы SBL начисляются и списываются для заказов приложения. Продажи, оформленные напрямую в Presto, баланс SBL не меняют.
- Автоматического переноса заказов и бонусного баланса в Presto нет. Сотрудник проводит продажу вручную.

## Backend и сборки

SQL-миграции и Edge Functions включены как исходники и история. Их наличие не подтверждает применение к конкретной базе. Не запускайте все миграции, функции синхронизации СБИС или deploy автоматически: настройки и состояние действующего VPS проверяются отдельно. Рабочий прайс-лист СБИС выбран владельцем — **67**.

Текущий VPS размещает также поиск и бот. Репозиторий клиентского приложения не содержит приватных серверных настроек, резервных копий и паролей. В этой публикации нет команды, которая заново разворачивает production backend.

В `eas.json` все профили передают публичную VPS-конфигурацию; `preview-vps`, `preview-push-vps`, `ios-store` и `ios-handoff` включают вход по звонку (единственный способ входа). `preview-push-vps` создаёт подписанный APK для внутреннего тестирования и включает клиентскую регистрацию push. Серверная отправка остаётся **выключенной**, таймеров рассылки нет. FCM V1 service account загружен владельцем непосредственно в EAS; `google-services.json` в репозитории содержит только клиентскую конфигурацию Firebase, не приватный ключ сервисного аккаунта. Для iOS отдельно требуются подпись Apple Developer и APNs; unsigned-архив на iPhone не устанавливается.

Последний APK: **[SBL 1.0.0 (7)](https://expo.dev/artifacts/eas/L8gMEnEzQSjMuaWKaAOhANSmQunG-1PpAqPbAFH-dnk.apk)**, EAS build `559fa5e7-8240-4c3f-8d18-97a4e40efb8d`, статус FINISHED 27.11.2026. Проверены ZIP CRC, бинарный manifest (`com.shikky.sbl`, versionCode 7), arm64 и отличие JS bundle от APK6. SHA-256: `72d352746d2b5bab3a8518a5e179eb6909f530fb7ab04ad4f37b2b6a717d3060`. APK не хранится в Git. Фото/прокрутку/клавиатуру, заказ/бонусы/удаление и контролируемые push ещё нужно пройти на устройстве; успешная сборка не закрывает эти проверки.

Миграция от 27.11.2026 добавляют серверную изоляцию App Review: демо-заказы скрыты из обычной очереди сотрудников, не оплачиваются и не отправляют уведомления. Демо-номер задаётся только на сервере. Миграция требует установленной схемы и приватного `sbl.review_phone`; её нельзя запускать как автономный универсальный установщик. Реальный демо-вход и checkout ещё требуют проверки.

Напоминание о возвращении настроено по решению владельца: **7 дней после последнего оплаченного и выданного заказа**, с отдельным согласием пользователя. Учитывается дата заказа, а не последнее открытие приложения. Push-миграции и HTTPS-маршруты уже установлены на VPS; установщики повторно не запускать, рассылку включать только для согласованного теста собственного устройства.

## Работа с репозиторием

Основная ветка — `main`. Перед правками обновляйте её: над проектом работает несколько разработчиков. Не коммитьте `.env`, токены, пароли, дампы, пользовательские выгрузки, `node_modules`, экспортированные bundle и временные копии. Публичный `anon`-ключ допустим в клиенте; защиту данных обеспечивают серверные права и RLS.

Публикация в GitHub обновляет исходники. Действующие установки приложения, серверные функции и база от одного `git push` не обновляются.
