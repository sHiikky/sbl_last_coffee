# SBL — приложение кофейни

React Native / Expo (SDK 54) приложение для сети кофеен «SBL» (Томск). Backend — Supabase. Подробности, схема и решения — в `README.md`; здесь только то, что нужно знать перед правками.

## Стек и запуск
- Expo 54, React 19, React Native 0.81, `@react-navigation` (bottom-tabs + native-stack)
- Пакетный менеджер — npm (`package-lock.json`). Запуск: `npm install`, затем `npm start` / `npm run web`.
- Если `npm start` не подходит: `node node_modules/expo/bin/cli start --web --port 8081`.
- Dev-сервер иногда держит порт 8081 — найти процесс (`netstat -ano | grep 8081`) и завершить.
- На машине мало памяти: сервер может быть остановлен системой, закройте лишние вкладки браузера.

## Структура
- `App.js` — корень: табы (Главная/Меню/Корзина/Профиль) + модальный экран товара; состояние корзины, заказов, избранного и активного заказа здесь, дальше пропсами.
- `screens/` — Home, Menu, Product, Cart, OrderSuccess, OrderHistory, Profile, Loyalty.
- `components/` — UI. Единая карточка товара — `ProductCard.js` (`QuickProductCard.js` — реэкспорт). Остальное: `Chip`, `QuantityStepper`, `ToggleSwitch`, `Badge`, `PrimaryButton`, «голографические» элементы.
- `lib/` — `supabaseClient`, `catalogService` (каталог из Supabase), `orderService` (RPC `create_order`, идемпотентность, recovery), `promoService`, `bonusConfig`.
- `hooks/` — `useOrderStatus`, `useBonusAccount` (один общий источник и одна подписка).
- `loyalty/` — «Серия SBL» (посещения подряд, награда — десерт в подарок), чистый domain-слой; самопроверка: `node loyalty/loyaltyService.selfcheck.js`.
- `kassa-terminal/index.html` — отдельная веб-панель кассира (чистый HTML/JS), запускать через статический сервер, не `file://`.
- `theme/tokens.js` — токены дизайна. `data/products.js` — только утилиты (`formatPrice`, `cartKey`, точки/слоты самовывоза).
- `supabase/migrations/` — актуальная схема и последовательные миграции; состояние рабочей базы и контракт описаны в `README.md`.

## Модель данных
- Ключ строки корзины — `cartKey(id, modifiers, preparationNote)`: UUID товара, отсортированные добавки с количеством на одну порцию и нормализованное пожелание. Размеры остаются отдельными товарами СБИС. Разные наборы добавок или пожелания не объединяются.
- Оформление через `create_pickup_order`: сервер считает цены, проверяет quote v2, контакт, принадлежность сессии, точку и время. `total` после скидок, до бонусного списания. У подарочного десерта бесплатна база, добавки платные; SBL10 считается с оставшейся после подарка суммы.
- Рабочее время 11:00–20:00 Asia/Tomsk, приготовление 3–5 минут. Последний новый заказ — 19:55, существующий идемпотентный повтор возвращается и после закрытия. Единственная точка `lenina-72`.
- Статусы меняет staff RPC `update_order_status`; выдача из `ready` требует подтверждения полученных денег. Продажа в СБИС отмечается вручную, отдельной отметкой; автоматического экспорта нет.
- Бонусы, кэшбек и право на подарок подтверждает бэкенд. «Серия SBL» получает состояние через RPC; AsyncStorage хранит локальный кэш.

## Дизайн-правила
- Только токены из `theme/tokens.js`: цвета, радиусы (10/16/22/28), отступы, тени. Не хардкодить `#fff` и произвольные числа.
- Один радиус карточек (22), тень только у карточек первого уровня; акцент «Светлый минерал» `#B74924` — только для действий.
- Текст не мельче 12 px, зоны нажатия не меньше 44 px, главный CTA — `PrimaryButton`; оформление заказа и товара используют утверждённый `variant="holo"`.
- Голографические эффекты — точечно, не на каждом экране.
- Шрифты карточек — выбранный Onest: название15/400, цена16/600, ровные разряды, название занимает две строки по20px для выравнивания цен. Большой заголовок шторки товара сохраняет отдельный размер. Не менять без просьбы.

## Известные особенности
- `react-native-url-polyfill/auto` не резолвится Metro через pnpm-симлинки на Windows — в `lib/supabaseClient.js` ручной `setupURLPolyfill()`.
- Встроенный `expo start --tunnel` сломан. Показ другу — `start-tunnel.ps1` (свой ngrok в `ngrok3/`).
- Realtime должен быть включён для `orders` и `order_items` (Supabase → Database → Publications), иначе статус заказа не обновляется.
- Анонимный вход должен быть включён в Supabase (Authentication → Sign In / Providers); в локальном `supabase/config.toml` он выключен.
- Вход по телефону подготовлен через настоящий Supabase OTP (6 цифр), но отключён `EXPO_PUBLIC_PHONE_AUTH_ENABLED=false` до настройки провайдера. Любой код больше не принимается; локальный телефон не является аккаунтом. Подтверждённый аккаунт берётся только из Auth; гость может оставить неподтверждённый контакт при заказе.
- Push использует opt-in, приватные токены и серверную очередь, по умолчанию отключён до настройки native credentials/worker. Удаление аккаунта — честный запрос в очередь сотрудников, не мгновенное удаление.
- Контакты и юридические документы пока помечены «Нужно заполнить перед запуском» по решению владельца; реальные данные не выдумывать.
- Новые миграции 20261029100000/20261029110000 локально проверены и 29 октября вручную выполнены владельцем в Supabase: для обеих получено «Success. No rows returned». Итоговый read-only аудит структуры/прав: 64/64 PASS, включая OVERALL; вывод сохранён в `work/pickup-checkout/production-postdeploy-results-20261029.json`.
