## Включение
1. Сделать резервную копию рабочей БД.
2. В SQL Editor именно проекта кофейни выполнить целиком supabase/migrations/20261106100000_app_promo_codes.sql. Нужны уже установленные миграции pickup checkout и product_catalog_admin. Миграция транзакционная и отказывается заменять неизвестную версию checkout.
3. Выполнить work/promo-codes/verify-deployment.sql: все строки должны быть PASS.
4. Обновить веб-панель kassa-terminal целиком и собрать новую версию приложения из этих исходников. Старые APK знают только SBL10; новые произвольные промокоды требуют обновления приложения.
5. Войти сотрудником → Промокоды → Новый промокод → заполнить → включить → сохранить. Сначала проверить пробным заказом с известной суммой, затем отменить его через панель.

## Правила
- Латинские буквы, цифры, дефис и подчёркивание, 2–32 символа; регистр не важен. Уникальный код и отдельное внутреннее название.
- Процент (0 < x ≤ 100) либо сумма в рублях. Ограничение максимальной скидки; скидка не превышает стоимость участвующих позиций.
- Минимум и максимум всей корзины до скидок включительно. Пустой максимум — без ограничения.
- Все товары, выбранные UUID товаров или основные категории приложения. Добавки входят в стоимость выбранного товара.
- Сроки вводятся по Томску (UTC+7), независимо от часового пояса рабочего компьютера. Начало включительно, окончание исключительно. Неактивные/будущие/истёкшие коды не работают.
- Сначала подарок за серию (одна базовая позиция), потом промокод на оставшуюся участвующую сумму, потом списание бонусов. Один промокод на заказ. Лимиты числа использований и персональные коды в эту версию не входят.
- Создание/изменение только через RPC сотрудника; список кодов недоступен покупателям. Повтор сохранения после потери ответа безопасен, конфликт версии сохраняет форму.
- Окончательная цена и условия всегда проверяются create_pickup_order. Изменение условий после предварительного расчёта отклоняет устаревшую сумму; уже созданный заказ возвращается при идемпотентном повторе.
