# Меню из СБИС в приложении — что сделано и что нужно развернуть

## Что уже изменено в коде приложения (сделано автоматически)

- `data/products.js` — убран весь захардкоженный каталог напитков; оставлены только `formatPrice`, `cartKey`, `getProductById`, точки/время самовывоза и `DESSERT_CATEGORY` (нужно программе лояльности).
- `lib/catalogService.js` (новый файл) — грузит меню из таблицы Supabase `products`.
- `App.js` — при старте приложение подтягивает меню из Supabase (`fetchVisibleProducts`) и прокидывает его во все экраны; корзина упрощена (один товар = одна строка, без размера/молока/добавок).
- `screens/MenuScreen.js`, `screens/HomeScreen.js` — категории меню теперь берутся из реальных данных СБИС (Авторские, Напитки Классика, Спэшл меню, Сытное/Десерты), а не из старого списка "Кофе/Не кофе/Еда".
- `screens/ProductScreen.js` — убраны блоки "Размер / Молоко / Температура / Добавки" (как вы и просили — в реальном меню каждый вариант уже отдельная позиция со своей ценой).
- `screens/CartScreen.js`, `components/profile/OrderHistoryCard.js` и связанные файлы — обновлены под новую структуру товара.
- `loyalty/loyaltyService.js` — награда "десерт в подарок" теперь ищет товары по реальной категории СБИС ("Сытное/Десерты"), а не по старому "dessert" — иначе награда бы тихо перестала работать.

Все файлы я проверил на синтаксические ошибки (прогнал через тот же парсер, что использует React Native) — ошибок нет. Но саму сборку приложения (`expo start`) я не запускал — это стоит сделать вам, я не могу выполнять команды на вашем компьютере напрямую.

## Что нужно развернуть в Supabase (это должны сделать вы — у меня нет доступа к вашему проекту Supabase)

### Шаг 1 — создать таблицу

Supabase Dashboard → SQL Editor → вставить содержимое файла `supabase-products-schema.sql` целиком → Run.

### Шаг 2 — создать Edge Function синхронизации

Это уже обновлённая версия функции — с защитами: если СБИС вдруг вернёт заметно меньше товаров, чем в прошлый успешный запуск, синхронизация не применяется автоматически; если у уже известного товара цена скачет более чем в 3 раза — эта конкретная цена не обновляется, остальное (название, фото) обновляется как обычно. Каждый запуск (успешный, аномальный, с ошибкой) пишется в таблицу `sync_runs` и присылается вам в Telegram.

1. Supabase Dashboard → Edge Functions → Create a new function → имя **`sync-sbis-catalog`**.
2. Вставить в редактор содержимое файла `sync-sbis-catalog.ts` целиком → Deploy.
3. Там же (или в Settings → Edge Functions → Secrets) добавить секреты — **три первых это те же значения, что вы уже используете в `test-sbis-catalog-final.js`**, никому больше их не показывайте:
   - `SBIS_APP_CLIENT_ID` = `4402856400799386`
   - `SBIS_APP_SECRET` = (значение "Защищённый ключ")
   - `SBIS_SECRET_KEY` = (содержимое скачанного файла сервисного ключа)
   - `TELEGRAM_BOT_TOKEN` = токен вашего бота (необязательно, см. ниже)
   - `TELEGRAM_CHAT_ID` = id чата, куда слать уведомления (необязательно, см. ниже)

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` добавлять не нужно — Supabase сам даёт их каждой Edge Function.

Если `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` не заполнить — функция просто не будет слать уведомления, всё остальное продолжит работать как обычно. Заполнить их можно в любой момент позже.

#### Как получить токен и chat_id для Telegram-уведомлений

1. В Telegram напишите боту **@BotFather** команду `/newbot`, придумайте имя — он даст вам токен вида `123456:ABC-DEF...`. Это и есть `TELEGRAM_BOT_TOKEN`.
2. Напишите вашему новому боту любое сообщение (например "привет") — это нужно, чтобы у него появилась переписка с вами.
3. Откройте в браузере `https://api.telegram.org/bot<ваш_токен>/getUpdates` — в ответе найдите `"chat":{"id": ЧИСЛО, ...}` — это число и есть `TELEGRAM_CHAT_ID`.
4. Если хотите слать уведомления в отдельный чат/канал, а не себе в личку — добавьте бота туда и повторите шаг 3, написав что-нибудь в этот чат перед этим.

### Шаг 3 — запустить первый раз вручную и проверить

В терминале (или PowerShell):
```
curl -X POST "https://<ваш-project-ref>.supabase.co/functions/v1/sync-sbis-catalog" -H "Authorization: Bearer <anon-ключ-из-lib/supabaseClient.js>"
```
Должен вернуться JSON вида `{"ok":true,"totalFetched":168,"sellableItems":151,"inserted":151,"updated":0,"categories":[...]}`.

### Шаг 3.1 — где смотреть здоровье синхронизации

Table Editor → `sync_runs` — там строка на каждый запуск: время, статус (`success`/`error`/`skipped_anomaly`), сколько товаров нашлось, сколько добавилось/обновилось, и если был скачок цены — список этих товаров в `price_anomalies`. Обычно за этим следить не нужно — Telegram сам напишет, если что-то пошло не так.

### Шаг 4 — проверить, что реально видно в приложении

Функция при первой синхронизации сама включает `is_visible = true` только для 4 уже проверенных категорий меню (Авторские, Напитки Классика, Спэшл меню, Сытное/Десерты) — то есть после первого запуска меню в приложении уже должно наполниться автоматически, без ручной работы. Откройте Table Editor → `products`, чтобы убедиться, и при желании вручную поправьте `is_quick_pick`/`badge` у нескольких напитков — они отвечают за секцию "Быстрый выбор" на главном экране.

### Шаг 5 — расписание НЕ нужно (цены и так меняются редко)

Раз в кофейне цены почти не меняются — не имеет смысла дёргать СБИС каждый час "на всякий случай". Никакой Cron можно вообще не настраивать: просто запускайте синхронизацию вручную (та же команда curl из шага 3) в тот момент, когда реально что-то поменяли в СБИС — новый напиток, новая цена. Так синхронизация происходит именно тогда, когда вы этого хотите, а не по таймеру вслепую.

Если всё же хочется подстраховки на случай, если забудете запустить руками — можно поставить Cron раз в 2–3 дня (Dashboard → Edge Functions → `sync-sbis-catalog` → Cron), это уже не создаёт лишней нагрузки и не противоречит идее "обновляем редко, потому что и меняется редко".

## Важно проверить перед боевым запуском

1. Запустите приложение локально (`expo start`) и откройте вкладку "Меню" — убедитесь, что напитки и цены отображаются, категории переключаются, добавление в корзину и оформление заказа работают.
2. Фотографий у большинства товаров по-прежнему нет (см. предыдущий разбор каталога) — экран покажет фирменную серую заглушку SBL вместо фото, это не баг.
3. Секция "Быстрый выбор" на главной сейчас покажет первые товары меню (т.к. ни один пока не помечен `is_quick_pick`) — поправьте вручную в Supabase, если хотите там конкретные напитки.
4. Если увидите красный экран ошибки при запуске — пришлите мне текст ошибки, разберём сразу.
