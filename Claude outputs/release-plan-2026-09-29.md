## Первым делом

Зайти в СБИС → Номенклатура и посмотреть, что там уже есть — фото, описания, КБЖУ. Пункты ниже написаны исходя из состояния на момент последней проверки через API (77 из 83 товаров без фото, КБЖУ заполнено меньше чем у 15 позиций), а не факта после личного захода в СБИС.

## Часть 1 — ближний спринт

Всё, что можно закрыть без внешних согласований — доступ к СБИС уже есть (можно писать в Номенклатуру).

### Контент: фото, описания, КБЖУ
- [ ] Аудит Номенклатуры СБИС ★ — открыть все 83 позиции, отметить у кого есть фото/описание/КБЖУ, у кого пусто.
- [ ] Залить фото для позиций без фото — начать с «Быстрого выбора» и хитов на Главной, их видно чаще всего.
- [ ] Написать описания там, где пусто — решить, кто пишет, для единого тона.
- [ ] Заполнить КБЖУ там, где пусто ★ — решить источник цифр (спросить у кофейни состав/вес или считать самим). Приложение уже показывает блок КБЖУ, если заполнено минимум 3 значения из 4.
- [ ] Проверить, как фото из СБИС доходит до приложения ★ — через Edge Function `sync-sbis-catalog` (запуск вручную). Раньше адреса картинок с `api.sbis.ru` не открывались в браузере — проверить хотя бы одно фото на реальном устройстве после первой синхронизации, прежде чем заливать остальные 76.

### Технический долг — деньги и награды
- [ ] Награда «десерт в подарок» не проверяется сервером — сервер верит клиенту, что награда положена; перенести проверку серии на сервер.
- [ ] Восстановленный после сбоя заказ не гасит награду — награда остаётся доступной повторно, день не засчитывается в серию.
- [ ] Корзина не сверяется с актуальным каталогом — цена и раздел товара берутся из локального хранилища и не обновляются при изменении в Supabase.
- [ ] «Повторить заказ» берёт старую цену — должен подтягивать текущую цену товара.

### Технический долг — касса и синхронизация
- [ ] Касса не проверяет прошлый статус заказа перед обновлением — риск отката уже завершённого заказа.
- [ ] Касса грузит Supabase SDK с внешнего CDN без фиксации версии — захостить копию локально в `kassa-terminal/`.
- [ ] Каталог не отфильтровывает позиции-модификаторы СБИС — видимый модификатор можно добавить в корзину, заказ упадёт на сервере без понятной причины.

## Часть 2 — дальше, крупными блоками

Порядок такой, чтобы каждый блок был отдельно тестируемым.

1. **Оплата** — выбрать шлюз (ЮKassa / CloudPayments / СБП), подключить тестовый режим, затем боевой. Сейчас заказ создаётся без оплаты вообще.
2. **Передача заказа в СБИС** — обратная связь: заказ из приложения должен попадать на кассу СБИС, статус — синхронизироваться назад. Нужны ключи СБИС для этой части API (не Номенклатура, другой контур).
3. **Вход по телефону** — сейчас анонимный вход, «аккаунт» привязан к установке, а не к человеку. Нужен SMS-провайдер.
4. **Юридическое** — политика конфиденциальности, пользовательское соглашение, согласие по 152-ФЗ — обязательны для модерации в сторах.
5. **Мониторинг** — Sentry до релиза, не после первого падения; отдельно отслеживать сбои Supabase/СБИС/оплаты.
6. **Сборка и тестирование** — EAS Build → внутреннее тестирование → закрытое тестирование. У Google обязательны 12+ живых тестировщиков 14 дней подряд — таймер стоит запускать заранее.
7. **Публикация** — Google Play (поэтапная раскатка) + App Store + RuStore параллельно.
