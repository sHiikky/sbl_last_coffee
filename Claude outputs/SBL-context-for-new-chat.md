## Что это за проект

Мобильное приложение кофейни **SBL Coffee** (React Native / Expo) — меню, корзина, оформление заказа на самовывоз, программа лояльности. Разработка ведётся вдвоём (я + братик/напарник), без отдельного QA/DevOps, через вайб-кодинг с Claude.

Проект лежит на компьютере в `F:\sbl_coffe\sbl-coffee-app-master`, репозиторий на GitHub: **https://github.com/K0lumiQ/sbl-coffee-app** (приватный).

## Технологический стек

- **React Native 0.81 + React 19** на **Expo SDK 54** (managed workflow)
- Навигация — **React Navigation** (`bottom-tabs`: Главная/Меню/Корзина/Профиль + `native-stack` поверх для карточки товара и т.д.)
- UI — самописные компоненты на чистом `StyleSheet` (никакого UI-кита, `react-native-paper` в зависимостях — неиспользуемый legacy)
- `expo-image` (картинки товаров с кэшем), `expo-linear-gradient`, `expo-haptics`, `@expo/vector-icons` (Ionicons)
- **Supabase** — единственный бэкенд: Postgres, Anonymous Auth, Realtime (статус заказа), Edge Functions (Deno)
- `@react-native-async-storage/async-storage` — локальный кэш корзины/избранного/истории заказов
- `react-native-web` — то же приложение открывается и в браузере (`expo start` → клавиша `w`)
- `kassa-terminal/index.html` — отдельная лёгкая HTML-страничка для кассы/бариста (supabase-js прямо с CDN, без сборки)
- TypeScript подключён (`tsconfig.json`), но реально весь код на `.js`
- Package manager — **npm** (в Windows PowerShell все команды через `.cmd`: `npm.cmd install`, `npx.cmd expo start` — либо один раз выполнить `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, чтобы работали обычные команды без `.cmd`)

## Интеграция с СБИС — текущий статус

- Таблица `products` в Supabase синхронизируется из СБИС Edge Function-ом `sync-sbis-catalog` — **только вручную по запуску**, никакого автоматического крона (сознательное решение: цены в кофейне меняются редко).
- Защита синка: дедуп по `sbis_id`, новые позиции скрыты до ручной проверки (`is_visible=false` по умолчанию), анти-аномалия по цене (>3× разницы не применяется автоматически), журнал в таблице `sync_runs`, Telegram-уведомления.
- Поверх сырых категорий СБИС — ручная кураторская разметка: `menu_category`/`menu_subcategory` (Напитки/Еда/Десерты/Магазин + подкатегории вроде «Кофе», «Шу», «Супы и сытное» и т.д.), `display_name`, `image_override_url` — эти поля синк никогда не перезаписывает.
- **Чего ещё нет**: обратной передачи заказа в СБИС, бонусов через СБИС (сейчас своя логика в `loyalty/loyaltyService.js`, не связана с реальной бонусной программой СБИС для очных клиентов), идентификации по телефону (сейчас anonymous auth). Полный список того, что нужно уточнить у СБИС и что делать дальше — расписан в отдельном отчёте, см. ниже.

## Экран «Меню» — самая проработанная часть, сейчас в фокусе

Один сплошной скроллящийся список (не отдельные экраны по категориям): фиксированные чёрная шапка (лого + поиск) и ряд главных категорий (Все/Напитки/Еда/Десерты) — они НЕ являются частью скролла (обычные соседи FlatList в дереве, не sticky/overlay), сам FlatList начинается физически ниже них.

Внутри — навигационная **state machine** с тремя режимами (`idle` / `programmatic-scroll` / `subcategory-relayout`), которая решает, кто сейчас имеет право менять подсветку активной категории наверху:
1. Явный тап по главной категории — подсветка меняется мгновенно, scroll-spy блокируется на время автоскролла.
2. Тап по под-категории (второй уровень навигации, локальный фильтр внутри раздела) — главная категория "приколота" к текущему разделу, не пересчитывается.
3. Только когда ничего из вышеперечисленного не происходит — обычный ручной скролл, и scroll-spy сам определяет активную категорию (viewability-based, с порогом видимости 55% и защитой от дребезга на границах секций).

Отдельно решена проблема «короткой последней секции» (если в Десертах отфильтровать маленькую под-категорию типа «Шу», список физически не может докрутиться, чтобы Десерты не выглядели как «Еда» наверху) — через адаптивный нижний отступ + резервную проверку «пользователь у самого конца списка → активна последняя категория».

Сделаны оптимизации, чтобы карточки товаров не перерисовывались зря при смене активной категории: `React.memo` на карточке, мемоизация `renderItem`/`keyExtractor`/колбэков скролла.

**Файлы этой части**: `screens/MenuScreen.js`, `components/QuickProductCard.js`, `components/Chip.js`, `lib/catalogService.js`.

Последнее состояние: вся эта архитектура реализована и залита на GitHub. Ожидается ручное тестирование по чек-листу (проверка сценариев вроде «быстро потыкать все категории подряд», «отфильтровать Шу — сверху должны остаться Десерты», «долистать до конца — активна последняя категория» и т.д.) — если после тестов найдутся конкретные баги, их нужно описывать как конкретные сценарии (что нажал → что увидел → что ожидал), а не пересылать заново весь список требований.
