Что сделано полностью

Готово
Синхронизация каталога СБИС → Supabase

Edge Function sync-sbis-catalog забирает каталог из СБИС и заливает в таблицу products (upsert по sbis_id). Запуск только вручную по кнопке — без автоматического крона, так решено сознательно.

Готово
Защита синхронизации

Дедупликация по sbis_id; новые позиции скрыты по умолчанию до ручной проверки; анти-аномалия по цене (отклонение >3× не применяется автоматически); журнал каждого запуска в sync_runs; Telegram-уведомление о результате.

Готово
Кураторская разметка меню

~90 позиций размечены по понятной покупателю таксономии (Напитки/Еда/Десерты/Магазин + подкатегории) — поверх технических папок СБИС. Ручные поля (menu_category, display_name, image_override_url и т.д.) синхронизация никогда не перезаписывает.

Готово
Экран меню в приложении

Полностью переделан: единый скролл, фиксированная шапка и навигация по разделам, scroll-spy, локальные фильтры по подкатегориям, карточки без «пустых» зон у товаров без фото.

Готово
Инфраструктура Supabase

Переезд на новый проект выполнен, Anonymous Sign-In и Realtime (orders/order_items) включены. Исправлен баг лояльности — «бесплатный десерт» больше не начислялся на дорогие сэндвичи.

2

Сделано частично

Частично
Синхронизация — только в одну сторону

Каталог едет СБИС → приложение. Обратной синхронизации (заказ из приложения → СБИС) нет вообще.

Частично
Бонусная программа

В приложении своя, самописная логика (loyalty/loyaltyService.js) — никак не связана с бонусами СБИС для очных клиентов. Два разных мира клиентов — главная незакрытая задача интеграции.

Частично
Идентификация пользователя

Сейчас анонимная (Supabase Anonymous Sign-In) — только чтобы был auth.uid(). Для связки с СБИС (обычно по телефону) этого недостаточно.

Частично
Заказы

Пишутся в Supabase (orders/order_items), но нигде не передаются в СБИС — касса/учёт о них не узнают.

Частично
Классификация каталога

3 позиции не размечены («Кедровая сказка», «Шоковзлёт», «Очень странные дела по-сибирски») — нужно уточнить у кофейни, что это. Раздел «Магазин» размечен, но выключен (is_visible = false).

3

Что осталось сделать

  1. Уточнить у СБИС: есть ли API бонусной программы (клиент по телефону, баланс, списание/начисление), API передачи заказа, тестовый (sandbox) контур, актуальный pointId.
  2. Заменить анонимную авторизацию на идентификацию по номеру телефона (SMS-код) — без этого нельзя связать пользователя приложения с клиентом СБИС.
  3. Передача заказа в СБИС после оплаты в приложении (сначала в тестовый контур, если есть).
  4. Бонусы через СБИС вместо самописной логики — после этого старую логику и kassa-terminal можно выводить из эксплуатации.
  5. Обратная синхронизация статуса заказа СБИС → Supabase → приложение (Realtime уже настроен, не хватает источника обновлений от СБИС).
  6. Ежедневная сверка Supabase / СБИС / платежей — дешевле поймать рассинхрон на нескольких тестовых заказах, чем на потоке боевых.
  7. Мелкое по каталогу: доразметить 3 позиции выше, решить судьбу раздела «Магазин».

⚠️ Чего в коде нет и что нужно взять напрямую из Dashboard

Эти значения нигде не хранятся в проекте — так и задумано, из соображений безопасности. Посмотреть/пересоздать их может тот, у кого есть доступ владельца или админа проекта:

  • SUPABASE_SERVICE_ROLE_KEY — секретный ключ Edge Function sync-sbis-catalog (Project Settings → API → service_role). Никогда не должен попадать в код приложения или репозиторий.
  • SBIS_APP_CLIENT_ID, SBIS_APP_SECRET, SBIS_SECRET_KEY — секреты СБИС, заданы в Edge Functions → sync-sbis-catalog → Secrets.
  • TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID — опционально, для уведомлений о синхронизации.
